MINECRAFT MOBA — UNIFIED AUTHORITATIVE PROJECT HANDOFF

Current design state: September 8, 2026

PURPOSE

This document consolidates the current authoritative state of the Minecraft MOBA project across:

Levels / universal progression

Archetypes

Objectives and XP

Constructs

Routes

Supply Lines

Worksites

Default map structure

World generation

Wilderness design

Resource ecology

Hunger / expedition range

Map scale

Previous procedural map experiments

The next playable prototype

It is intended to be sufficient context for continuing the project in a fresh session.

Where earlier exploratory ideas conflict with later corrections, the later correction is authoritative.

In particular:

Constructs do not necessarily grant an XP multiplier.

Development does not necessarily operate inside Constructs.

Construction and Development do not require one another.

Supply Lines do not currently require a physical traced path.

Routes and Supply Lines are distinct systems.

The old objective-method XP hierarchy is nixed.

Base authored Routes no longer receive a movement-speed bonus in the current test.

L1 = 10 food and L3 Hunger = 12 food are prototype test settings, not globally finalized progression values.

1. THE GAME / WORLD THESIS

Minecraft is the base systemic language.

The game should not feel like a conventional MOBA arena covered in Minecraft textures. The Minecraft world itself is the strategic board.

Terrain, hunger, mining, construction, caves, food, animals, villages, routes, logistics, resources, infrastructure, farming, transport, and player modification of the environment should remain real gameplay.

The broad world-state arc is:

generated Minecraft world
→ discovered
→ traversed
→ extracted
→ constructed
→ developed
→ connected
→ supplied
→ contested

This is an emergent ecosystem, not a mandatory linear sequence.

Ordinary Minecraft verbs should generally remain available to everyone.

Progression and archetypes should primarily gate:

exceptional efficiency;

exceptional potency;

systemic recognition;

higher-order infrastructure;

rather than saying:

"You are not the correct class, therefore you cannot build/mine/travel/craft."

2. LEVEL STRUCTURE AND POWER CURVE

Level range

Matches progress from:

Level 1 → Level 30

Level 30 intentionally references Minecraft's familiar enchanting threshold.

The exact relationship between MOBA levels and vanilla Minecraft XP/enchanting remains unresolved.

Power curve

The intended progression fantasy is:

Early game

A significantly constrained Minecraft character.

Midgame

Approximately complete / vanilla-capable Minecraft player.

Late game

Increasingly supernormal class/archetype expression.

Level 30

A highly realized class whose exceptional systems significantly alter how the player interacts with the Minecraft world.

Vanilla Steve is therefore approximately a midgame reference point, not the maximum state.

Approximately Level 16 has been used as the conceptual vanilla-baseline transition, but this is not locked.

Change in progression composition

Early → mid progression should contain substantial growth in fundamental physical Minecraft capacity.

Mid → late progression should increasingly derive power from:

specialization;

archetype mechanics;

class mechanics;

efficiency;

potency;

rather than indefinitely increasing generic:

health;

hunger;

inventory;

movement speed;

damage;

mining speed.

3. THREE PROGRESSION LAYERS

3.1 Universal progression

Automatic progression establishes the minimum capability available to everyone.

Principal universal capacities currently under consideration:

Health

Hunger

Inventory

A player should eventually reach approximately vanilla capability in these systems even without investing specialization choices into them.

3.2 Permanent progression/specialization choices

At selected progression points, players can permanently accelerate or specialize particular capacities or systems.

The generic term Development choices should not be used because Development is one of the seven archetypes.

The exact name and cadence remain unresolved.

Early examples include:

Health

Hunger

Inventory

A useful balancing principle:

Investment should let a player experience a new practical capability several levels before the universal baseline naturally reaches it.

Examples:

Hunger investment allows a meaningful expedition earlier.

Inventory investment allows a meaningful provisioning/haul configuration earlier.

Health investment allows deliberate exposure to danger earlier.

Specialization should accelerate or exceed the universal curve.

It should not replace it.

3.3 Class/archetype progression

Class mechanics establish the exceptional ceiling.

Therefore:

Universal progression establishes the floor.
Specialization creates differentiation above or ahead of that floor.
Class/archetype progression establishes the exceptional ceiling.

Generic investment should never completely replace a class whose archetype owns the relevant system.

4. HEALTH, HUNGER, AND INVENTORY DESIGN METHOD

Do not begin by choosing arbitrary schedules such as:

+1 heart every X levels;

+1 hunger icon every Y levels;

+1 slot every Z levels.

Instead:

Determine what activities should be practical at a progression phase.

Determine what every player can do.

Determine what an invested player can do earlier/better.

Choose the smallest numerical change that reliably causes that gameplay transition.

Numbers should follow desired Minecraft behavior.

5. ROUGH UNIVERSAL CAPABILITY PHASES

These are conceptual phases, not locked level thresholds.

Level 1

Players are substantially below vanilla physical capability.

Desired consequences:

local planning matters;

mistakes matter;

expedition range matters;

inventory forces loadout decisions;

ordinary Minecraft is possible but constrained.

Early levels (~3–5)

Players remain below vanilla capacity.

Nearby activity should be reliable.

Larger undertakings require preparation.

Investment begins to make specific activities practical earlier.

Developing phase (~8)

Ordinary PvP/PvE and wilderness activity become increasingly practical.

The character remains recognizably below complete vanilla physical capability.

Approaching midgame (~12)

Most ordinary Minecraft activities should be viable.

Physical limitations can still matter.

Invested capacities may approach, reach, or potentially exceed their corresponding vanilla values before the universal baseline does.

Vanilla-baseline transition (~16 conceptual)

Every player approaches roughly vanilla-like:

Health

Hunger

carrying capability

Invested players may already exceed those baselines.

Late game

Vanilla capability becomes the floor.

The majority of exceptional power increasingly comes from:

class mechanics;

archetype systems;

specialization.

6. HEALTH

Health should be calibrated against recognizable Minecraft survival thresholds.

Questions include:

How many normal attacks are survivable?

What falls become survivable?

How forgiving are ordinary mob encounters?

Can a player survive long enough to disengage?

At what point does the environment stop being disproportionately lethal?

A Level 1 value around 5 hearts / 10 HP has been discussed as more plausible than 3 hearts / 6 HP.

This is not final.

Half-heart / +1 HP increments may provide useful granularity.

Also not final.

7. HUNGER AS EXPEDITION CAPACITY

Hunger is primarily:

internal expedition / endurance / provisioning capacity

rather than merely another bar.

Higher Hunger can allow a player to:

sprint longer;

stay away from supplies longer;

tolerate detours;

search larger uncertain areas;

carry less food for the same journey;

retain safer return reserves.

Hunger investment should not automatically grant speed.

This matters particularly for Exploration balance.

Hunger and Inventory intentionally overlap

Hunger:

"My body can operate longer between resupply."

Inventory:

"I can carry more resupply with me."

A low-Hunger player may use inventory slots for food.

A high-Hunger player can use those same slots for other purposes.

This overlap is desirable.

8. CURRENT HUNGER TEST VALUES

These are prototype test settings, not finalized universal progression rules.

L1 map test

5 hunger icons

10 food points

0 / effectively 0 saturation

L3 Hunger test

6 hunger icons

12 food points

0 / effectively 0 saturation

This represents:

+1 hunger icon

Sprint cutoff

Use vanilla behavior.

Sprint becomes unavailable at:

3 hunger icons

6 food points

No custom sprint threshold is required.

Design implication

At L1:

10 food → sprint cutoff at 6

Sprint-capable reserve:

4 food points

~16 exhaustion

At L3 Hunger:

12 food → cutoff at 6

Reserve:

6 food points

~24 exhaustion

Therefore the +1 icon test represents:

+20% total displayed Hunger;

approximately +50% pre-cutoff sprint-capable reserve.

This is a strong early logistics/traversal upgrade and should be tested intentionally.

9. INVENTORY

Inventory progression should be evaluated in meaningful loadout categories rather than abstract slot counts.

Examples of low-level decisions:

tools vs food;

blocks vs supplies;

expedition provisioning vs return haul;

multiple construction materials vs utility;

extraction yield vs preparedness.

The correct question is:

"What meaningful additional equipment/material category can this player now bring or return with?"

Inventory being universally useful does not invalidate Logistics.

Everyone benefits from carrying capacity.

Logistics classes manipulate:

storage;

carrying;

transport;

transfer;

distribution;

at exceptional/team-facing scales.

11. EFFICIENCY VS POTENCY

Efficiency

Perform approximately the same useful task for less:

time;

input;

resource expenditure;

risk;

effort;

logistical burden.

Potency

Perform:

more;

a stronger version;

a larger-scale version;

or something an ordinary player could not normally accomplish through that system.

This distinction should remain explicit throughout class and progression design.

Potential expressions:

13. EXPLORATION / MOVEMENT BALANCE

Permanent unconditional movement speed is unusually strategically powerful.

It affects:

POI arrival;

Pioneer/Match First exploration;

reinforcement timing;

escapes;

pursuit;

Worksite contests;

objective timing;

territorial reach;

resource acquisition;

return-from-death timing.

Small speed bonuses can compound into opportunity leads.

Therefore:

Equivalent local combat/stat power does not imply equivalent strategic power.

Current early Exploration direction:

movement efficiency before movement potency

Examples:

sprint efficiency;

traversal efficiency;

endurance;

specialized environmental traversal.

Raw:

speed;

high jump;

unusual vertical mobility;

should be introduced cautiously and may fit later progression or specific classes.

14. CONSTRUCTION — BLOCK EFFICIENCY

A current Construction scaling vocabulary concept is Block Efficiency.

A Construction-specialized player may create more useful world geometry from a fixed carried material supply.

Possible implementation:

after enough eligible placements, a placement costs no block;

or a block is refunded after enough eligible placements.

Anti-exploit requirement

Efficiency-generated blocks are valid world geometry but should not become recoverable material sources.

If destroyed, they should not drop collectible items.

This should survive, where technically possible:

ordinary mining;

explosions;

pistons;

environmental destruction;

transformations.

They remain valid for:

shelter;

bridges;

defenses;

collision;

functional construction;

infrastructure validation.

Block provenance may need invisible tracking.

This is Construction vocabulary, not necessarily a universal passive shared by every Construction class.

15. CONSTRUCTION ↔ DEVELOPMENT

Construction and Development intentionally have adjacent vocabulary.

Useful distinction:

Construction

Establish/manipulate useful built places.

Development

Improve/mature productive world states.

They will often interact.

They may frequently become colocated.

However:

Construction does not require Development.

Development does not require Construction.

Development does not necessarily operate inside Constructs.

Their relationship is synergy, not prerequisite.

16. INFRASTRUCTURE RECOGNITION PRINCIPLE

A major cross-system rule:

Progression can gate systemic recognition and exceptional infrastructure benefits without gating normal Minecraft behavior.

Anyone can:

build a house;

create a road;

place storage;

farm;

manually transport items;

construct a fortress.

Specialized progression may allow recognition of:

a Construct;

a Route;

a Supply Line;

a Development area/system;

other empowered infrastructure.

17. CONSTRUCTS

The older Construction-submission model is being redesigned.

A player can physically build regardless of Construct access.

Progression may grant:

Construct designation;

Construct slots/capacity;

maximum recognized size;

recognition radius;

other benefits.

A promising model is that recognized influence partly derives from the validated physical extent of the submitted structure, capped by the player's current progression limit.

This allows early-game recognized construction size to be gated without preventing players from physically building larger structures.

Important correction

Do not treat "Constructs grant an allied XP multiplier" as a required/current universal rule.

That concept was explored and at one point documented as a leading implementation, but was subsequently demoted.

The desired broader principle remains:

Useful infrastructure should prove its strategic value through actual use rather than through a trivial one-time submission reward.

Exactly how Constructs provide that team-facing systemic value remains open.

Open Construct questions

slots;

size;

validation;

influence;

functionality;

XP interaction, if any;

enemy interaction;

destruction/damage;

scaling.

18. ROUTES

There are two different Route contexts in the current design:

authored map Routes, generated as part of Default;

player-recognized Routes, potentially established through progression.

They share traversal language but should not automatically be assumed identical in implementation.

Player-recognized Route topology

Current working idea:

The player physically traverses the desired path, and that traversal defines the Route.

Exact:

drawing;

submission;

validation;

width;

branching;

remain unresolved.

Current early Route benefit

Preferred systemic language:

improve sprint/traversal efficiency

rather than generic speed.

Infrastructure that already exists can improve repeated travel without determining who wins the original race to an unknown place.

19. ROUTE TEST MECHANIC

For the next Default-map playable test:

base authored Routes receive no movement-speed bonus;

their clean/direct terrain is already useful;

additionally, Routes provisionally grant approximately 10% lower locomotion-generated exhaustion.

Conceptual values:

Sprinting

0.10 exhaustion/block
→ approximately 0.09

Sprint-jumping

0.20 jump component
→ approximately 0.18

Ordinary jumping

0.05
→ approximately 0.045

Do not apply this reduction to:

combat;

regeneration;

mining;

non-locomotion hunger costs.

This deliberately double-counts Route value for the first prototype:

Routes are geometrically cleaner.

Routes also receive modest artificial locomotion efficiency.

This is a test mechanic, not final Route progression.

Do not restore the earlier +10% movement-speed idea as the default.

20. SUPPLY LINES

Supply Lines are the current leading team-facing Logistics infrastructure concept.

Current topology

Unlike Routes, which are currently envisioned as being drawn through traversal:

A Supply Line is currently envisioned as being established using storage at a start point and storage at an endpoint.

The two storage endpoints establish the connection.

Do not prematurely document whether the intervening connection is:

physically traced;

pathless;

node-based;

route-following;

vulnerable terrain;

abstract logistics.

That remains unresolved.

Core fantasy

Upstream stored items gradually replenish/transfer to downstream storage.

Examples:

Mine storage
→ Base storage

Farm storage
→ Production storage

Base storage
→ Worksite storage

Production storage
→ Forward storage

The key benefit is persistent resource availability even when the Logistics player is elsewhere.

Potential scaling

Supply Line count;

range;

throughput;

transfer frequency;

capacity;

filtering;

destinations;

branching;

network sophistication;

reliability.

Later high-potency Logistics may allow infrastructure to replenish players directly.

Example fantasy:

"This position is supplied."

21. ROUTES VS SUPPLY LINES

Route

Question:

How efficiently can players repeatedly travel through this connection?

Current establishment concept:

pure traversal

Core value:

traversal efficiency

Supply Line

Question:

How efficiently can resources become available where the team needs them?

Current establishment concept:

start storage + end storage

Core value:

distribution/replenishment

Do not collapse these systems together merely because they both connect places.

22. EXTRACTION

Extraction concerns useful acquisition/access to world material.

Possible expressions:

faster extraction;

tool efficiency;

difficult-material access;

unusual detection;

larger-scale extraction;

exceptional excavation.

Destroying an enemy fortress is not inherently Extraction.

The resource/access purpose matters.

Mole

Mole's Sifth Sense is an existing class-specific Extraction example.

It detects underground resources and scales in:

radius;

rate;

specificity.

World systems such as Worksites should preserve meaningful specialist advantage without making Mole mandatory.

23. PRODUCTION / KITFIGHTER

Kitfighter currently has:

Primary: Combat

Secondary: Production

Do not list Extraction as a current Kitfighter archetype.

Salvage

Current Kitfighter direction:

Crafting equipment using at least 3 units of a Primary Material grants:

1 Salvage for that material

Salvage is material-specific.

Recovery thresholds:

Level 0: 6 Salvage

Level 8: 5 Salvage

Level 16: 4 Salvage

Level 24: 3 Salvage

Consume the required Salvage to recover:

2 units of that Primary Material

These thresholds belong to Kitfighter.

They do not establish a universal class-progression cadence.

Covered With Diamonds

Ultimate:

temporarily upgrades iron armor/tools to Diamond;

equipment later reverts.

Current overdrive direction:

knockback resistance;

movement speed.

Exact unlock timing is unresolved.

It should eventually be calibrated against universal progression/economy.

Equipment economy

Current direction:

Iron is the highest combat-equipment tier routinely/sustainably available to ordinary players.

This should be an economic result, not an equip ban.

Diamond remains legal and vanilla-powerful.

Permanent Diamond represents exceptional investment.

Diamonds compete with other strategic uses.

Natural diamonds may remain scarce.

Mining Worksites can create reliable exceptional concentrations.

If everyone reaches full Diamond, first diagnose the resource economy rather than banning Diamond.

24. XP PHILOSOPHY

Legitimate resource attainment grants XP directly. The XP system does not need to determine whether each acquired resource was ultimately used well; usefulness is presumed through the resource economy.

Prefer objective, legible evidence over subjective judgments of strategic value.

Examples may include:

legitimate resource attainment;

exploration discoveries;

major neutral encounters;

objective contribution;

infrastructure interaction/use.

Exploration XP

Existing concepts include:

Team First discovery

Match First / Pioneer discovery

This is another reason early unconditional movement speed is dangerous.

Important correction

The following hierarchy is nixed:

destruction = lowest XP

defender elimination = medium XP

specialized objective interaction = highest XP

Objective solution methods should produce strategically different consequences, not be globally ranked by XP multipliers.

Useful vocabulary:

29. DEFAULT MAP THESIS

Default should feel like Minecraft first and a competitive MOBA second.

Generation philosophy:

Let Minecraft generate Minecraft-like geography, then constrain, inspect, validate, select, and modestly adjust it for competitive play.

Do not:

construct a conventional MOBA arena and disguise it with Minecraft terrain.

The world itself is strategic.

30. DEFAULT MACRO-GEOGRAPHY

Teams oppose one another:

North ↔ South

The strongest environmental gradient is:

West ↔ East

This orthogonality is deliberate.

North/South

North homeland

South homeland

competitive team opposition

authored routes projecting into shared wilderness

West

Major mountain/highland geography.

East

Ocean/coast geography.

This allows strong environmental asymmetry without making one team inherently "the mountain team" or "the ocean team."

Exact terrain varies by seed.

The macro relationship is guaranteed.

33. AUTHORED ROUTES

Each team has:

three major authored Route branches

projecting from its homeland.

Villages and major POIs have visible authored Route infrastructure leading
toward them.

A destination does not necessarily sit directly on a Route, and players remain
free to approach it off-route, but this Route relationship is an intentional
part of Default's generated infrastructure rather than merely a likely
proximity relationship.

Routes may also lead toward other strategically useful Wilderness areas.

They are physical Minecraft infrastructure, not invisible lanes.

Players may freely leave them.

Large POIs generally have meaningful route relationships.

Routes should remain cleanly traversable.

Avoid arbitrary:

trees blocking roads;

pointless jump taxes;

random walls;

decorative impassability.

Difficult terrain should make off-route traversal meaningfully more expensive rather than making designed infrastructure unpleasant.

77. AUTHORITATIVE SHORT FORM

If most other context is lost, preserve the following:

Minecraft MOBA uses a Level 1–30 progression curve where players begin significantly constrained, approach vanilla Minecraft capability around midgame, and increasingly express supernormal archetype/class power afterward.

The seven archetypes are Combat, Exploration, Construction, Extraction, Production, Development, and Logistics. Archetypes govern exceptional efficiency and potency rather than reserving ordinary Minecraft actions.

Infrastructure recognition can be progression-gated without gating normal building/travel/storage. Constructs, Routes, and Supply Lines are distinct. Development does not require Constructs or Construction. Player Routes are currently envisioned as being drawn through traversal. Supply Lines are currently envisioned as start-storage → end-storage resource-distribution connections. Constructs do not currently have a settled XP-multiplier mechanic; their systemic benefit remains open, but recognized infrastructure should create persistent/team-facing value through actual use rather than merely paying a trivial submission reward.

Default is a Minecraft-first competitive world with North/South team homelands, three authored Route branches per team, a large shared Wilderness, western mountain/highland geography, and eastern coast/ocean geography.

Homelands guarantee viable baseline Minecraft development. Wilderness opportunities may be asymmetric but should be competitively evaluated.

The generator should create plausible Minecraft geography, identify actual resource instances, derive strategic geography from them, make modest corrections, and reject unsuitable seeds rather than over-authoring them.

Default guarantees strategically fundamental vocabulary where omission would break systems. Current prototype guarantees include cow/sheep/pig/chicken through at least four broad livestock ranges, separate horses, wheat/carrots/potatoes, sand, gravel, and western high-altitude snow ecology. Ores and village resources exist physically.

The current map prototype uses L1 = 10 food / 0 saturation and L3 Hunger = 12 food / 0 saturation strictly as test states. Vanilla sprint cutoff remains at 6 food / 3 icons.

Base authored Routes receive no movement-speed bonus in the current test. They are clean/direct physical infrastructure and provisionally reduce locomotion-generated exhaustion by approximately 10%.

The current map-scale hypothesis is approximately +25% macro linear Wilderness/resource separation implemented nonuniformly. Near-home geography changes little; deeper Wilderness, resource separation, forest depth, Route separation, and mountain depth receive most of the added space.

The immediate next artifact is a new playable Minecraft Java Default-map
prototype testing whether this added physical room creates genuine expeditions,
distinct resource geography, useful infrastructure, ecological identity, and
enough empty connective terrain while remaining recognizably Minecraft.

The exact target Java version remains unresolved and must be chosen before
generation. A modern version is preferred if an embedded datapack is used
natively, but this preference is not yet a finalized version requirement.
