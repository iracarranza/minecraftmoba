## Authority and scope

This is an audit record, not a design decision. The authoritative domain
sources are `classes.md`, `objectives.md`, and `maps.md`. `chathandoff.txt` is
a consolidated handoff dated September 8, 2026; it is a valuable design source
but does not override those documents. The browser wiki is non-authoritative.

## Design state by confidence

### Established design

- Minecraft is the systemic language; ordinary Minecraft verbs remain broadly
  available, while classes provide exceptional efficiency and potency.
- The seven archetypes are Combat, Exploration, Construction, Extraction,
  Production, Development, and Logistics.
- Default is a procedural, Minecraft-first map grammar with North/South team
  opposition, a shared Wilderness, western highlands, and eastern coast/ocean.
- Fundamental resource vocabulary is guaranteed by category, not necessarily
  mirrored, abundant, fixed, or near a homeland.
- Objective solutions should differ by costs and world consequences, not by a
  universal XP hierarchy. Resource attainment directly grants XP.
- Worksites reveal exceptional physical opportunities; players still excavate,
  extract, and transport them.

### Working design

- Equivalent homeland opportunity rather than literal symmetry.
- Three authored Route branches per homeland and a variable western snow
  ecology.
- The detailed class drafts, objective interactions, seed-selection pipeline,
  and opportunity-based fairness validation.
- The Level 1–30 broad progression curve and approximate midgame
  vanilla-capability landmark.

### Prototype/test parameters

- Default Scale Test's approximately +25% nonuniform macro separation.
- L1 10 food / 0 saturation and L3 Hunger 12 food / 0 saturation.
- Base authored Routes' provisional approximately 10% locomotion-exhaustion
  efficiency, with no movement-speed bonus.
- Four mixed livestock ranges, separate horses, and baseline crop occurrences.
- Travel bands, earlier dimensions, and all exact resource populations/counts.

### Historical or superseded material

- P0 through P2D greyboxes, the 50-variant experiment, and seed `920260900`
  are references rather than canonical Default.
- The prior objective-method XP ranking, Route movement-speed bonus, rigid
  Supply Chain crop reward, and Mining Outpost-as-ore-dispenser model are
  superseded.
- The wiki's old objective XP table, literal homeland mirroring language,
  Construction-submission Mining Outpost, and 1,300 x 1,000 footprint are
  stale snapshots, not current rules.

### Unresolved questions

- Exact universal Health/Hunger/Inventory schedule and progression-choice
  cadence.
- Construct benefit, validation, influence, and enemy interaction.
- Player Route validation and Supply Line topology/transfer behavior.
- Objective sequence, structural validation, Aether exposure/disablement,
  contribution accounting, Worksite apparatus details, and Supply Chain.
- Target Java version, world-writing method, exact generation pipeline, and
  final map dimensions.

## Cross-source reconciliation

The canonical Markdown documents agree with the current handoff on the major
map, class, objective, resource, and prototype-test corrections. No conflict
between canonical Markdown documents was found in this pass.

The handoff contains material that is not yet represented by a canonical
domain document:

- the universal-progression framework: automatic capacity, permanent
  specialization choices, conceptual phase descriptions, and Health/Hunger/
  Inventory design method;
- Constructs, player-recognized Routes, and Supply Lines as distinct
  infrastructure systems;
- the detailed Route/Hunger operating-range model and datapack technical
  limitation; and
- the explicit Java-version compatibility issue and pre-generation inspection
  checklist.

This material should be assigned to new canonical documents only after the
project chooses document ownership/names. It has not been elevated silently.

  the repository uses lowercase Markdown files; browser edits are localStorage

- The wiki has no Kitfighter canonical draft and preserves superseded objective

  deliberately synchronized.

  through `P2D_FINAL.zip`, the P1 travel matrix, the resource-ecology pipeline,
  accepted-seed data, resource audits, a Java world, and a datapack/test
  harness.

## Recommended next milestone

Create a **generation feasibility spike**, not the playable map: select the
target Minecraft Java version and a compatible world-writing/authoring path;
inventory available libraries/tools; then commit a tiny reproducible empty
world-generation proof plus a validation-report schema. That resolves the
technical prerequisite identified by the design without prematurely choosing a
seed, final balance values, or map implementation.
