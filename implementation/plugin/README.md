# Phase 1 plugin

Target: **Paper 1.21.11, Java 21, Gradle 8.14.3**. `SPEC.md` is the sole design
input. No playable map is generated by this project.

Build: `./gradlew clean test build`. Install `build/libs/minecraft-moba-0.1.0-SNAPSHOT.jar`
in a Paper 1.21.11 server's `plugins/` directory. Start once to generate config.
Restart after config edits. Invalid numeric configuration fails plugin startup.

Admin commands require `moba.admin` (operator by default), and target online players:

- `/moba setlevel <player> <level>` sets level and clears progress toward the next level.
- `/moba setclass <player> <classId>` stores an opaque ID; `none` clears it.
- `/moba xp <player> <nonnegative amount>` awards command-only XP.
- `/moba reset <player>` resets class, progression, choices and transient mode.
- `/moba debug <player>` prints authoritative data and freshly derived capacity.

PDC is updated after commands, on join/quit, and plugin shutdown. Paper flushes
player PDC to disk with its normal player saves; corrupt/unsupported payloads are
not overwritten. Mode and derived capacity are never persisted. Choices are retained
when administratively lowering level; higher-level effects are ignored until eligible.
Protocol constants (zero, level-one baseline, vanilla 20 hunger / 36 storage slots)
and serialization version numbers are structural, not balance values. All growth
and progression values come from config. Rewards ship empty.

## Inventory policy

Slot locking cancels clicks (including creative clicks), drags, number-key swaps,
offhand swaps, unsafe pickups and automatic inventory transfers. At partial capacity,
shift insertion into player inventory and double-click collection are conservatively
cancelled because their destination/source traversal is not exposed by the event.
Vanilla hoppers cannot feed a player inventory; the move handler also guards custom
inventory-transfer events. Administrative capacity reduction leaves existing items in
place in their now-locked slots. Raising capacity restores access without moving them.

User-approved enrollment policy: an occupied offhand containing another item blocks
enrollment. Empty it yourself and run `/moba join`; the plugin never overwrites it.
The sole inventory write creates a fresh tagged FILLED_MAP in an empty offhand.
Offhand map interaction with entities/blocks is blocked, including item frames.
Enrolled players retain inventory on death through vanilla keep-inventory semantics.
The map renderer is a one-time placeholder; no minimap is implemented.
